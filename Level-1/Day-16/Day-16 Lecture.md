## 1. What Is a Sequence?

A **sequence** is an Oracle database object that automatically generates numeric values.

Sequences are commonly used to generate:

- Primary-key values.
- Employee IDs.
- Customer IDs.
- Order numbers.
- Transaction numbers.

```text
Sequence
   |
   v
Generates: 1001, 1002, 1003, ...
   |
   v
Values can be inserted into a table
```

### Why Use a Sequence?

| Benefit | Explanation |
| --- | --- |
| **Automatic numbering** | Oracle generates values without manually finding the largest existing ID. |
| **Multi-user support** | Multiple users can safely request new numbers. |
| **Independent object** | One sequence can be used by one or more tables. |
| **Customizable** | Starting value, increment, limits, cycling, and caching can be configured. |

### Create Sequence Syntax

```sql
CREATE SEQUENCE sequence_name
START WITH initial_value
INCREMENT BY increment_value
[MINVALUE minimum_value | NOMINVALUE]
[MAXVALUE maximum_value | NOMAXVALUE]
[CYCLE | NOCYCLE]
[CACHE cache_size | NOCACHE];
```

### Create Sequence Example

```sql
CREATE SEQUENCE employee_seq
START WITH 1001
INCREMENT BY 1
NOCYCLE
CACHE 20;
```

| Sequence Option | Purpose |
| --- | --- |
| `START WITH` | Defines the first generated value. |
| `INCREMENT BY` | Defines how much each new value increases or decreases. |
| `MINVALUE` / `MAXVALUE` | Defines the sequence limits. |
| `CYCLE` | Restarts after reaching a limit. |
| `NOCYCLE` | Stops generating values after reaching a limit. |
| `CACHE` | Keeps sequence values in memory for better performance. |
| `NOCACHE` | Does not preallocate sequence values in memory. |

### `NEXTVAL` and `CURRVAL`

```sql
SELECT employee_seq.NEXTVAL
FROM dual;
```

`NEXTVAL` generates and returns the next sequence number.

```sql
SELECT employee_seq.CURRVAL
FROM dual;
```

`CURRVAL` returns the latest value generated by the sequence in the current session. It cannot be used before `NEXTVAL` is called in that session.

### Insert Data Using a Sequence

```sql
INSERT INTO employees (
    employee_id,
    employee_name,
    status
)
VALUES (
    employee_seq.NEXTVAL,
    'Aung Aung',
    'ACTIVE'
);
```

### Alter and Remove a Sequence

```sql
ALTER SEQUENCE employee_seq
INCREMENT BY 5
NOCACHE;
```

```sql
DROP SEQUENCE employee_seq;
```

### Important Sequence Rules

- Sequence numbers may contain gaps.
- Rolling back a transaction does not return a used sequence number.
- A sequence does not automatically insert values; the statement must use `NEXTVAL`.
- Multiple tables can use the same sequence.
- Dropping a sequence does not remove values already stored in tables.

## 2. What Is an Index?

An **index** is a database object that provides a faster path for locating rows in a table.

It works similarly to a book index:

```text
Without Index:
Search many table rows until a match is found

With Index:
Use indexed values to locate matching rows quickly
```

An index stores:

- Indexed column values.
- References to the corresponding table rows.

### Why Use an Index?

| Benefit | Explanation |
| --- | --- |
| **Faster searches** | Speeds up queries that filter indexed columns. |
| **Faster joins** | Helps Oracle match related rows between tables. |
| **Faster sorting** | May help queries using `ORDER BY`. |
| **Faster grouping** | May help some `GROUP BY` operations. |
| **Uniqueness enforcement** | Unique indexes prevent duplicate indexed values. |

### Index Example

```sql
CREATE INDEX employee_name_idx
ON employees (employee_name);
```

This index may improve the following query:

```sql
SELECT *
FROM employees
WHERE employee_name = 'Aung Aung';
```

> **Important:** creating an index does not guarantee Oracle will use it. The Oracle optimizer selects the access method it expects to be most efficient.

## 3. Automatically and Manually Created Indexes

Indexes can be created **automatically** by Oracle or **manually** by a database user.

### Automatically Created Indexes

Oracle normally creates a unique index automatically when a `PRIMARY KEY` or `UNIQUE` constraint is created, unless a suitable existing index can be used.

```sql
CREATE TABLE departments (
    department_id NUMBER PRIMARY KEY,
    department_name VARCHAR2(100) UNIQUE
);
```

Oracle can create indexes to support:

- The `PRIMARY KEY` on `department_id`.
- The `UNIQUE` constraint on `department_name`.

### Manually Created Indexes

A user creates a manual index to improve specific query patterns.

```sql
CREATE INDEX employee_department_idx
ON employees (department_id);
```

### Automatic vs Manual Indexes

| Feature | Automatically Created Index | Manually Created Index |
| --- | --- | --- |
| Created by | Oracle | User or DBA |
| Common reason | Support `PRIMARY KEY` or `UNIQUE` constraints | Improve query performance |
| Creation time | During constraint creation | When `CREATE INDEX` is executed |
| Design control | Mostly determined by constraint | Chosen by user or DBA |
| Removal | Usually managed with its constraint | Removed using `DROP INDEX` |

---

## 4. Common Oracle Index Types

| Index Type | Description | Common Use |
| --- | --- | --- |
| **B-tree index** | Default Oracle index; stores values in a balanced tree. | High-cardinality columns and general queries. |
| **Unique index** | Prevents duplicate combinations of indexed values. | Primary keys and unique business values. |
| **Composite index** | Contains two or more columns. | Queries that frequently filter multiple columns together. |
| **Bitmap index** | Uses bitmaps to represent values. | Low-cardinality data in data warehouses. |
| **Function-based index** | Stores the result of a function or expression. | Queries that filter using the same function. |

### Composite Index Example

```sql
CREATE INDEX employee_dept_status_idx
ON employees (department_id, status);
```

The column order matters. This index is most useful for queries beginning with the leading column, `department_id`.

### Function-Based Index Example

```sql
CREATE INDEX employee_upper_name_idx
ON employees (UPPER(employee_name));
```

It may improve:

```sql
SELECT *
FROM employees
WHERE UPPER(employee_name) = 'AUNG AUNG';
```

## 5. Guidelines for Index Creation

### Consider Creating an Index When

- A table is large.
- A column is frequently used in a `WHERE` condition.
- A column is frequently used in joins.
- A column contains many distinct values.
- Queries usually retrieve a small percentage of table rows.
- A foreign-key column is frequently used for joins or parent-row deletion.
- A combination of columns is frequently searched together.

### Avoid or Reconsider an Index When

- The table is small.
- Queries usually retrieve most rows from the table.
- The column contains very few distinct values in a transaction-heavy system.
- The indexed column is frequently updated.
- The table receives many `INSERT`, `UPDATE`, and `DELETE` operations.
- A similar index already exists.
- The index is rarely or never used.

### Index Creation Decision Table

| Situation | Index Recommendation | Reason |
| --- | --- | --- |
| Large table searched by employee ID | Create index | Queries retrieve a small number of rows. |
| Small lookup table | Usually unnecessary | A full table scan may be faster. |
| Column frequently used in joins | Consider index | Can improve row matching. |
| Column updated constantly | Use carefully | Every update must also maintain the index. |
| Low-cardinality column in OLTP | Usually avoid normal B-tree index | It may not filter enough rows. |
| Low-cardinality column in a data warehouse | Consider bitmap index | Bitmap indexes suit analytical filtering. |
| Existing composite index has the required leading columns | Avoid duplicate index | The existing index may already support the query. |

### Important Composite-Index Rule

For this index:

```sql
CREATE INDEX employee_dept_status_idx
ON employees (department_id, status);
```

| Query Filter | Likely Index Use |
| --- | --- |
| `department_id = 10` | Useful |
| `department_id = 10 AND status = 'ACTIVE'` | Useful |
| `status = 'ACTIVE'` only | Often less useful because `department_id` is the leading column |

**Easy memory tip:** place frequently filtered and selective leading columns carefully in a composite index.

## 6. Index Costs and Weaknesses

Indexes improve reading speed, but they are not free.

| Weakness | Explanation |
| --- | --- |
| **Additional storage** | Every index uses disk space. |
| **Slower DML** | Oracle must update indexes when table rows change. |
| **Maintenance** | Unnecessary or duplicate indexes must be monitored and removed. |
| **Poor design risk** | Incorrect column order may make a composite index less useful. |
| **Optimizer choice** | Oracle may choose not to use an index when a full table scan is cheaper. |

```text
More Indexes
    |
    +--> Faster reads in suitable queries
    |
    +--> More storage and slower data changes
```

## 7. Managing Indexes

### Create a Normal Index

```sql
CREATE INDEX employee_name_idx
ON employees (employee_name);
```

### Create a Unique Index

A unique index prevents duplicate combinations of its indexed values.

```sql
CREATE UNIQUE INDEX employee_email_uidx
ON employees (email);
```

### Create a Composite Index

```sql
CREATE INDEX employee_dept_status_idx
ON employees (department_id, status);
```

### View Current User's Indexes

```sql
SELECT
    index_name,
    table_name,
    uniqueness,
    index_type,
    status,
    visibility
FROM user_indexes
ORDER BY table_name, index_name;
```

### View Indexes for One Table

```sql
SELECT
    index_name,
    uniqueness,
    index_type,
    status
FROM user_indexes
WHERE table_name = 'EMPLOYEES';
```

Oracle normally stores unquoted object names in uppercase in data-dictionary views.

### View Indexed Columns

```sql
SELECT
    index_name,
    table_name,
    column_name,
    column_position
FROM user_ind_columns
ORDER BY index_name, column_position;
```

### View the Definition of an Index

```sql
SELECT DBMS_METADATA.GET_DDL(
    'INDEX',
    'EMPLOYEE_NAME_IDX'
)
FROM dual;
```

### Rebuild an Index

Rebuilding recreates the index structure.

```sql
ALTER INDEX employee_name_idx REBUILD;
```

It may be used after certain maintenance operations or when an index becomes unusable. Rebuilding should be done only when there is a real need.

### Rename an Index

```sql
ALTER INDEX employee_name_idx
RENAME TO employee_full_name_idx;
```

### Make an Index Invisible

An invisible index is maintained during DML but is normally ignored by the optimizer. It is useful when testing whether an index is still required.

```sql
ALTER INDEX employee_full_name_idx INVISIBLE;
```

Make it visible again:

```sql
ALTER INDEX employee_full_name_idx VISIBLE;
```

### Mark an Index Unusable

```sql
ALTER INDEX employee_full_name_idx UNUSABLE;
```

An unusable index cannot normally be used until it is rebuilt:

```sql
ALTER INDEX employee_full_name_idx REBUILD;
```

### Drop an Index

```sql
DROP INDEX employee_full_name_idx;
```

Dropping an index removes the index but does not remove its table data.

> **Warning:** do not directly drop an index that Oracle uses to enforce a `PRIMARY KEY` or `UNIQUE` constraint without first understanding the constraint dependency.

### Index Command Recap

| Task | Command |
| --- | --- |
| Create normal index | `CREATE INDEX index_name ON table_name (column_name);` |
| Create unique index | `CREATE UNIQUE INDEX index_name ON table_name (column_name);` |
| View indexes | Query `USER_INDEXES` |
| View indexed columns | Query `USER_IND_COLUMNS` |
| Rebuild index | `ALTER INDEX index_name REBUILD;` |
| Rename index | `ALTER INDEX old_name RENAME TO new_name;` |
| Hide index from optimizer | `ALTER INDEX index_name INVISIBLE;` |
| Restore optimizer visibility | `ALTER INDEX index_name VISIBLE;` |
| Remove index | `DROP INDEX index_name;` |

**Easy memory tip:** `CREATE INDEX` builds the access path, `USER_INDEXES` shows it, and `DROP INDEX` removes it.

## 8. Oracle Synonyms

A **synonym** is an alternative name for another database object.

Synonyms can refer to:

- Tables.
- Views.
- Sequences.
- Materialized views.
- Procedures and functions.
- Packages.
- Other synonyms.

```text
Long or qualified object name
HR.EMPLOYEES
      |
      v
Simple synonym
EMP
```

### Why Use Synonyms?

| Benefit | Explanation |
| --- | --- |
| **Simpler object names** | Replaces long or schema-qualified names with shorter names. |
| **Hide object ownership** | Users do not need to include the owner's schema name. |
| **Location transparency** | Can hide whether an object is local or accessed through a database link. |
| **Application flexibility** | Applications can use a stable synonym while the underlying object changes. |

> **Important:** a synonym does not copy data and does not automatically grant privileges.

### Private Synonym

A **private synonym** belongs to one schema and is normally available only to that schema.

```sql
CREATE SYNONYM emp
FOR hr.employees;
```

The schema can now use:

```sql
SELECT *
FROM emp;
```

Instead of:

```sql
SELECT *
FROM hr.employees;
```

### Public Synonym

A **public synonym** is available to all database users, but users still require permission on the referenced object.

```sql
CREATE PUBLIC SYNONYM emp_public
FOR hr.employees;
```

Creating or dropping a public synonym requires special system privileges.

### Private vs Public Synonym

| Feature | Private Synonym | Public Synonym |
| --- | --- | --- |
| Available to | One schema | All database users |
| Created using | `CREATE SYNONYM` | `CREATE PUBLIC SYNONYM` |
| Special privilege required | Usually no, within own schema | Yes |
| Recommended use | Schema-specific convenience | Shared object name used across schemas |

### Synonym for a Sequence

```sql
CREATE SYNONYM emp_seq
FOR hr.employee_seq;
```

```sql
SELECT emp_seq.NEXTVAL
FROM dual;
```

### Replace a Synonym

```sql
CREATE OR REPLACE SYNONYM emp
FOR hr.active_employees;
```

### Remove Synonyms

Remove a private synonym:

```sql
DROP SYNONYM emp;
```

Remove a public synonym:

```sql
DROP PUBLIC SYNONYM emp_public;
```

Dropping a synonym does not drop or modify the referenced database object.

### Important Synonym Rules

- A synonym stores an alternative object name, not object data.
- A synonym does not grant access privileges.
- Users must still have permission on the referenced object.
- A private synonym normally belongs to one schema.
- A public synonym is accessible by name to all users.
- Dropping a synonym does not drop the original object.
- If the referenced object is removed or renamed, the synonym may no longer work.

**Easy memory tip:** a synonym is a nickname for a database object.

## 9. PL/SQL: `IF` and `FOR LOOP`

**PL/SQL** means **Procedural Language/SQL**. It extends SQL with programming features such as variables, conditions, loops, procedures, functions, and exception handling.

### Basic PL/SQL Block

```sql
SET SERVEROUTPUT ON;

DECLARE
    v_message VARCHAR2(100);
BEGIN
    v_message := 'Hello PL/SQL';
    DBMS_OUTPUT.PUT_LINE(v_message);
END;
/
```

| Block Part | Purpose |
| --- | --- |
| `DECLARE` | Optional section for variables, constants, and cursors. |
| `BEGIN` | Starts the required executable section. |
| `EXCEPTION` | Optional section for handling errors. |
| `END;` | Ends the PL/SQL block. |
| `/` | Sends the completed block for execution in tools such as SQL*Plus. |

### `IF` Statement

An `IF` statement runs code only when a condition is true.

#### Simple `IF`

```sql
DECLARE
    v_salary NUMBER := 750000;
BEGIN
    IF v_salary > 500000 THEN
        DBMS_OUTPUT.PUT_LINE('High salary');
    END IF;
END;
/
```

#### `IF ... ELSE`

```sql
DECLARE
    v_status VARCHAR2(20) := 'ACTIVE';
BEGIN
    IF v_status = 'ACTIVE' THEN
        DBMS_OUTPUT.PUT_LINE('Employee can access the system');
    ELSE
        DBMS_OUTPUT.PUT_LINE('Employee cannot access the system');
    END IF;
END;
/
```

#### `IF ... ELSIF ... ELSE`

General structure:

```sql
IF condition_1 THEN
    statements_for_condition_1;
ELSIF condition_2 THEN
    statements_for_condition_2;
ELSIF condition_3 THEN
    statements_for_condition_3;
ELSE
    statements_when_no_condition_is_true;
END IF;
```

Oracle checks the conditions from top to bottom. It executes the first matching block and skips the remaining conditions.

```sql
DECLARE
    v_score NUMBER := 82;
BEGIN
    IF v_score >= 80 THEN
        DBMS_OUTPUT.PUT_LINE('Grade A');
    ELSIF v_score >= 60 THEN
        DBMS_OUTPUT.PUT_LINE('Grade B');
    ELSIF v_score >= 40 THEN
        DBMS_OUTPUT.PUT_LINE('Grade C');
    ELSE
        DBMS_OUTPUT.PUT_LINE('Fail');
    END IF;
END;
/
```

> Oracle PL/SQL uses `ELSIF`, not `ELSEIF`.

### PL/SQL `SELECT INTO`

In PL/SQL, a query that returns one row can store its column values in variables using `SELECT ... INTO`.

General structure:

```sql
SELECT column_1, column_2
INTO variable_1, variable_2
FROM table_name
WHERE condition;
```

The number, order, and compatible data types of the selected columns and variables must match.

#### Select One Employee Example

```sql
SET SERVEROUTPUT ON;

DECLARE
    v_employee_name employees.employee_name%TYPE;
    v_status employees.status%TYPE;
BEGIN
    SELECT employee_name, status
    INTO v_employee_name, v_status
    FROM employees
    WHERE employee_id = 101;

    DBMS_OUTPUT.PUT_LINE('Name: ' || v_employee_name);
    DBMS_OUTPUT.PUT_LINE('Status: ' || v_status);
END;
/
```

`%TYPE` declares a variable using the data type of an existing table column.

#### `SELECT INTO` with `IF ... ELSIF`

```sql
DECLARE
    v_salary employees.salary%TYPE;
BEGIN
    SELECT salary
    INTO v_salary
    FROM employees
    WHERE employee_id = 101;

    IF v_salary >= 1000000 THEN
        DBMS_OUTPUT.PUT_LINE('High salary');
    ELSIF v_salary >= 500000 THEN
        DBMS_OUTPUT.PUT_LINE('Medium salary');
    ELSE
        DBMS_OUTPUT.PUT_LINE('Entry-level salary');
    END IF;
END;
/
```

#### Handling `SELECT INTO` Exceptions

A normal `SELECT INTO` statement must return exactly one row.

```sql
DECLARE
    v_employee_name employees.employee_name%TYPE;
BEGIN
    SELECT employee_name
    INTO v_employee_name
    FROM employees
    WHERE employee_id = 101;

    DBMS_OUTPUT.PUT_LINE(v_employee_name);
EXCEPTION
    WHEN NO_DATA_FOUND THEN
        DBMS_OUTPUT.PUT_LINE('No employee was found');
    WHEN TOO_MANY_ROWS THEN
        DBMS_OUTPUT.PUT_LINE('The query returned more than one employee');
END;
/
```

| Result of `SELECT INTO` | Outcome |
| --- | --- |
| Exactly one row | Values are stored in the variables. |
| No rows | Raises `NO_DATA_FOUND`. |
| More than one row | Raises `TOO_MANY_ROWS`. |

**Easy memory tip:** SQL uses `SELECT`; PL/SQL uses `SELECT ... INTO` to place a single row into variables.

### `FOR LOOP`

A `FOR LOOP` repeats a block of code for a defined numeric range or query result.

#### Numeric `FOR LOOP`

```sql
BEGIN
    FOR i IN 1..5 LOOP
        DBMS_OUTPUT.PUT_LINE('Number: ' || i);
    END LOOP;
END;
/
```

- Oracle automatically declares the loop counter `i`.
- The counter begins at `1` and ends at `5`.
- The counter should not be manually changed inside the loop.

#### Reverse `FOR LOOP`

```sql
BEGIN
    FOR i IN REVERSE 1..5 LOOP
        DBMS_OUTPUT.PUT_LINE('Countdown: ' || i);
    END LOOP;
END;
/
```

Output order: `5`, `4`, `3`, `2`, `1`.

#### `IF` Inside a `FOR LOOP`

```sql
BEGIN
    FOR i IN 1..10 LOOP
        IF MOD(i, 2) = 0 THEN
            DBMS_OUTPUT.PUT_LINE(i || ' is even');
        ELSE
            DBMS_OUTPUT.PUT_LINE(i || ' is odd');
        END IF;
    END LOOP;
END;
/
```

### Cursor `FOR LOOP`

A cursor `FOR LOOP` processes rows returned by a query one at a time.

```sql
BEGIN
    FOR employee_record IN (
        SELECT employee_id, employee_name
        FROM employees
        WHERE status = 'ACTIVE'
    ) LOOP
        DBMS_OUTPUT.PUT_LINE(
            employee_record.employee_id || ': ' ||
            employee_record.employee_name
        );
    END LOOP;
END;
/
```

Oracle automatically opens the cursor, fetches each row, and closes the cursor.

### `IF` and `FOR LOOP` Comparison

| Feature | `IF` | `FOR LOOP` |
| --- | --- | --- |
| Purpose | Makes a decision | Repeats statements |
| Based on | Boolean condition | Numeric range or query rows |
| Ending syntax | `END IF;` | `END LOOP;` |
| Common use | Validation and business rules | Repeated processing |

### Important PL/SQL Rules

- End PL/SQL statements with semicolons.
- Use `:=` to assign a value to a PL/SQL variable.
- Use `=` to compare values.
- Use `ELSIF`, not `ELSEIF`.
- Close an `IF` statement with `END IF;`.
- Close a loop with `END LOOP;`.
- Use `DBMS_OUTPUT.PUT_LINE` to display output.
- Enable output using `SET SERVEROUTPUT ON` when required by the SQL tool.
- Use `SELECT ... INTO` when a PL/SQL query should return exactly one row.

**Easy memory tip:** `IF` chooses what to do; `FOR LOOP` chooses how many times to do it.

- **Sequence** သည် နံပါတ်များကို အလိုအလျောက်ထုတ်ပေးသော Oracle object ဖြစ်သည်။
- `NEXTVAL` သည် နောက် sequence number ကို ထုတ်ပေးပြီး `CURRVAL` သည် လက်ရှိ session တွင် နောက်ဆုံးထုတ်ထားသော number ကို ပြသည်။
- Sequence number များတွင် gap ရှိနိုင်ပြီး rollback လုပ်လျှင် အသုံးပြုပြီးသော number ပြန်မရပါ။
- **Index** သည် table row များကို ပိုမြန်စွာရှာနိုင်ရန် အသုံးပြုသော database object ဖြစ်သည်။
- `PRIMARY KEY` နှင့် `UNIQUE` constraint များအတွက် Oracle က index ကို အလိုအလျောက်ဖန်တီးပေးနိုင်သည်။
- Index များများဖန်တီးလျှင် read query မြန်နိုင်သော်လည်း `INSERT`, `UPDATE`, `DELETE` နှေးနိုင်သည်။
- Composite index တွင် column order သည် အရေးကြီးသည်။
- **Synonym** သည် database object တစ်ခုအတွက် အခြားအမည် သို့မဟုတ် nickname ဖြစ်ပြီး data ကို သီးခြားမသိမ်းပါ။
- Synonym ဖန်တီးခြင်းသည် referenced object ကို အသုံးပြုခွင့် privilege အလိုအလျောက်မပေးပါ။
- PL/SQL တွင် `IF` ကို condition စစ်ဆေးရန်အသုံးပြုပြီး `FOR LOOP` ကို statements များ ထပ်ခါတလဲလဲလုပ်ရန်အသုံးပြုသည်။
- PL/SQL တွင် `ELSEIF` မဟုတ်ဘဲ `ELSIF` ကိုအသုံးပြုရသည်။

> **စာမေးပွဲအတွက် အလွယ်မှတ်ရန်:** Sequence က number ထုတ်ပေးသည်။ Index က row ရှာဖွေမှုကို မြန်စေသည်။ Synonym က object အတွက် nickname ပေးသည်။ `IF` က ရွေးချယ်ပြီး `FOR LOOP` က ထပ်ခါတလဲလဲလုပ်သည်။
